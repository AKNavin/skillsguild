OPEN-SOURCE STRATEGY RESEARCH

Contribute a result someone can reproduce.

A useful strategy has clear rules, an inspectable backtest and everything an AI agent needs to run it again. Negative results and corrections belong here too.

Start with a complete trading idea

Specify the eligible universe, signal timestamp, entry, exit, position sizing, rebalancing and execution. Explain how the Indian implementation differs from its source research. A signal alone is not a complete strategy.

Include the research package

  • A concise SKILL.md with prerequisites, run command, expected outputs and limitations.
  • A machine-readable strategy configuration and runnable code with pinned dependencies.
  • A data manifest identifying provider, dates, adjustments, universe construction and rights. Include an authorised way to obtain the inputs.
  • Equity and drawdown series, calendar returns, closed trades, fees and slippage assumptions.
  • Meaningful tests for timing, accounting and missing data. Record the code and dataset versions used.

Make the evidence easy to interpret

Disclose all parameter selection and previously inspected periods. Identify survivorship bias, retrospective exclusions, simplified costs and proxy implementations. Report unsuccessful variants when they explain selection. Do not label a reused period as an untouched holdout.

Publish code and research you have permission to share. Keep API credentials, account data and restricted raw market data out of the repository. The local broker helper is for authentication and historical data access, not live order execution.

Submit through GitHub

Open an issue with the proposed strategy and data requirements, or send a pull request containing the complete reproducible package. Include the exact validation commands and their results. Reviewed contributions can then join the catalogue.

See the research methodology for the current accounting conventions and the AI guide for the reproduction workflow.
