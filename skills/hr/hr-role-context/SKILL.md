# Understand a role and its team

Build a private `role-brief.md` for a specific job before recruiting, onboarding or development work. Use the current job description, manager notes, team goals, work examples and optional `hr-context.md`.

## Build the brief
1. State role purpose, level, employment scope, reporting line, team interfaces, work location and schedule only where supplied. Identify outdated or contradictory descriptions.
2. Translate broad responsibilities into actual work: inputs, decisions, deliverables, tools, frequency and recipient. Ask the manager about the few gaps that change requirements.
3. Separate required capabilities from trainable skills and preferences. For each requirement, name the task that justifies it. Do not substitute prestige, demographic proxies or personality impressions for work evidence.
4. Capture expected early outcomes, available support and constraints. Treat targets as proposed until the accountable manager confirms them. Avoid inventing salary, work authorisation or qualification requirements.
5. Record source/date, unresolved assumptions, owner and review trigger. Conflicts between current policy and a manager's request remain visible; do not silently resolve them.

## Deliver
One-page brief: purpose; work table `responsibility | deliverable | collaborator | tools | success evidence`; essential/trainable/preferred capabilities; first-90-day outcomes; constraints; open questions. Add a context header with role ID, version and approved/proposed status.

**Check:** every essential capability maps to a real responsibility; every numerical target has a source or proposal label. This brief describes work, not the suitability of a particular person. Use it as the common input to job descriptions, interview kits and onboarding plans.

**Try:** “Turn this manager conversation and old JD into a current Customer Success Manager role brief; expose disagreements and missing success measures.”
