# Job-relevant work sample

## Inputs
Use a defined role capability, entry expectation, time budget, allowed tools and adjustment route. Optional private `role-brief.md` provides realistic work; `hr-context.md` provides candidate-facing tone. Confirm whether the skill is expected at entry or will be taught after joining.

## Workflow
1. Choose one representative task with an observable deliverable. Avoid a sprawling assignment that tests endurance, spare time or unrelated expertise.
2. Create complete synthetic materials: instructions, sample data, constraints and the submission format. Do not use confidential company problems or turn candidate work into unpaid production deliverables.
3. State the expected time, deadline/timezone, tool and AI-assistance rules, what will be assessed and how to request an equivalent accessible format. Apply the same policy consistently.
4. Define criterion-specific anchors before seeing submissions. Measure only the target capability; separate quality, reasoning and necessary task accuracy without counting the same evidence twice.
5. Complete a dry run using the supplied materials. Check ambiguity, missing data, task duration and alternative valid solutions. Record the result and fix defects before sharing; never claim a pilot happened if it did not.

## Deliver
A candidate brief, self-contained synthetic input pack, submission template and assessor guide: `criterion | observable evidence | anchor | acceptable alternatives`. Include an answer approach, known limitations and a short pilot log. Human reviewers assess candidates; the skill does not rank people or decide progression.

## Check
A candidate can finish with the provided inputs within the stated effort. Success does not require undisclosed knowledge, paid tools or personal data. Permitted AI/tool use is explicit.

Example: "Create a 30-minute customer-support triage exercise using fictional tickets, with a rubric and clear AI-tool rules."
